# Physical-client protocol validation

This is a separate validation gate from the namespace pilot in
`scripts/22_validate_protocol_pilots.sh`. Keep its attempts under
`runs/physical_validation/`; never pool them with namespace or main-matrix
results.

## Server setup

Start the recorded, project-owned listener from the server checkout:

```bash
cd /path/to/commu/traffic_experiment
sudo --preserve-env=PATH \
  EXPERIMENT_ENV_FILE="$PWD/server.lab.env" \
  LISTENER_PROFILE=high_ports \
  bash scripts/23_server_physical_listener.sh start
```

The listener records its PID, executable, process start identity, Caddy
configuration, and CA certificate. Ownership metadata lives under the stable
`PHYSICAL_LISTENER_STATE_ROOT`, outside topology-specific result roots, so a
one/two-GPU switch cannot hide a listener that still needs teardown. It does
not change firewall rules.

If a firewall change is necessary, allow only the exact client address or a
similarly narrow subnet:

```bash
sudo \
  CLIENT_CIDRS="203.0.113.42/32" \
  PHYS_IF=ens20f0 \
  LISTENER_PROFILE=high_ports \
  bash scripts/25_physical_firewall.sh apply
```

The address above is documentation-only. `CLIENT_CIDRS` is mandatory; IPv4
networks broader than `/24` are rejected. The helper discovers the destination
IPv4 address assigned to `PHYS_IF` (or verifies an explicit `PHYS_IP`) and binds
each UFW rule to both that address and interface. Use the same `PHYS_IF` for
cleanup. Apply records a unique rule tag and exact rule specification in
`firewall.state`; cleanup refuses name- or number-only deletion, preserves
pre-existing same-profile rules, and retains the state file if exact deletion
or post-deletion baseline verification fails.

## Build the self-contained client bundle

The frozen request manifest is intentionally not generated by the bundle
script. Supply the exact immutable JSONL used by the experiment and the exact
served-model name:

```bash
CLIENT_QA_MANIFEST=/path/to/frozen/requests_32.jsonl \
CLIENT_MODEL=Qwen/Qwen3.5-9B \
CLIENT_LISTENER_PROFILE=high_ports \
bash scripts/24_create_client_bundle.sh
```

Bundle creation fails if the manifest, CA certificate, runner environment, or
required source trees are absent. The archive contains:

- `traffic_experiment/traffic_measure/` and `locomo_eval/` Python source;
- the byte-for-byte frozen QA manifest and its checksum;
- the Caddy root CA certificate and checksum;
- the physical-client scripts and pinned client requirements; and
- non-secret client configuration only; no credential material.

The generated archive and checksum are under
`runs/physical_validation/handoff/`. Transfer both and verify the checksum
before extraction.

## Client setup

```bash
tar -xzf commu-client-bundle-v6.tar.gz
cd commu-client
python3 -m venv .venv-client
.venv-client/bin/pip install -r requirements-client.txt

# Edit config/client.env and set CAPTURE_INTERFACE.
set -a
source config/client.env
set +a
read -rsp "vLLM API key: " LOCAL_VLLM_API_KEY
printf '\n'
export LOCAL_VLLM_API_KEY

.venv-client/bin/python -c "import aioquic, httpx, locomo_eval"
bash traffic_experiment/scripts/run_physical_client.sh tls "${LISTENER_PROFILE}"
bash traffic_experiment/scripts/run_physical_client.sh h3 "${LISTENER_PROFILE}"
```

The aliases `tls13` and `http3` map to the same normalized runner values as
`tls` and `h3`.

## Measurement boundary

For each transport, the client script:

1. verifies the authenticated model endpoint and exact served-model name;
2. performs its TCP reachability calibration before capture;
3. creates a fresh append-only `attempt-NNN` directory;
4. starts the external packet capture;
5. sends exactly one `no_compression` request in cold-connection mode;
6. stops and flushes the capture;
7. verifies the normalized result transport and negotiated HTTP version;
8. rejects missing protocol, application, uplink, downlink, timestamp, MTU,
   offload, or HTTP/3 fallback evidence; and
9. binds that attempt's PCAP to the dynamically discovered result row.

Cold mode is deliberate here: a warm-mode runner performs an unmeasured
connection warm-up that would contaminate a one-request external capture. Warm
sessions remain a separate experiment.

Only a fully validated attempt receives `VALIDATION_COMPLETE`. Failed or
interrupted attempts and their error metadata remain untouched. A later run
skips network activity only when it finds a marked result whose PCAP still
exists and matches its recorded SHA-256. The marker also binds the exact model,
frozen-manifest SHA-256, endpoint/CA/capture configuration, transport, and fixed
generation settings (condition, seed, temperature, output ceiling, and cold
connection mode); changing any of them creates a new attempt.

## Acceptance gate

Do not use physical-client evidence until all of these hold:

- TLS: negotiated HTTP/1.1, TCP packets > 0, TLS records > 0, and both
  directions > 0.
- HTTP/3: negotiated HTTP/3, UDP packets > 0, QUIC packets > 0, both directions
  > 0, and zero same-endpoint TCP fallback packets.
- The capture packet timestamps overlap the recorded application request and
  contain no traffic outside that request window beyond the documented clock
  tolerance.
- Maximum decoded IPv4 packet length does not exceed `CLIENT_MTU`, and no
  offload-sized frames make on-wire sizes ambiguous.
- The attached PCAP path and SHA-256 match the validated capture.

## Teardown

Remove only this project's recorded state, then verify listener closure:

```bash
sudo --preserve-env=PATH \
  EXPERIMENT_ENV_FILE="$PWD/server.lab.env" \
  LISTENER_PROFILE=high_ports \
  bash scripts/23_server_physical_listener.sh stop
sudo PHYS_IF=ens20f0 LISTENER_PROFILE=high_ports \
  bash scripts/25_physical_firewall.sh cleanup
ss -ltnp | grep -E ':8443|:8543' || true
ss -lunp | grep -E ':8444|:8544' || true
```
